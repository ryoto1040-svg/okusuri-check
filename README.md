# お薬チェック

朝・夕のお薬を確認して、この端末・このブラウザの`localStorage`に保存するシンプルなWebアプリです。ログイン、端末間の共有、プッシュ通知、外部データベース、サーバーAPIはありません。画面ファイルの取得後、薬のチェックと保存に外部サービスへの通信は使いません。

## 使える機能

- 朝：胃ろうからの薬、夜間尿量に応じた点鼻。
- 夕：胃ろうからの薬、眠剤、点鼻、耳鼻科の鼻の薬、点眼。
- 尿量110g以上（110gちょうどを含む）は朝の点鼻が対象、110g未満は対象外、未入力は確認待ち。
- 実施時に確認画面を表示し、端末の現在時刻を保存。
- 実施済みを通常のタップでは解除しない。訂正は理由と確認が必要で、元の実施時刻・訂正日時を履歴に保存。
- 日本時間0:00に新しいチェックリストへ切り替え。アプリ再表示時にも日付を確認。過去の記録は保持。
- 日付別の履歴、一時薬の有効・無効、バックアップの書き出しと確認付き復元。
- スマートフォン向けレイアウト、ホーム画面追加、初回準備後のオフライン利用。

登録された尿量条件を表示する仕組みであり、医学的な判断は行いません。実際に投与したことを確認してから記録してください。

## 開発・ローカル確認

Node.js 22以降とpnpm 11以降を使います。クラウドのアカウント、環境変数、秘密鍵、Javaは不要です。

```sh
pnpm install
pnpm dev
```

開発画面は `http://127.0.0.1:5173`。オフラインとPWAは、本番用ビルドのプレビューで確認します。

```sh
pnpm test
pnpm build
pnpm preview
```

プレビューは `http://127.0.0.1:4173`。ログイン画面はなく、そのまま使えます。上部に「オフライン利用の準備ができています」と表示されるまで、最初は通信可能な状態で開いてください。

ブラウザの通しテストは `pnpm build` のあとに `pnpm test:e2e`。テストは必要に応じてプレビューサーバーを起動します。Windowsではインストール済みChromeを使います。他の場所にある場合は`CHROME_PATH`を指定するか、`pnpm exec playwright install chromium`でテスト用ブラウザを用意します。テストは専用の一時ブラウザ領域を使い、普段使っているブラウザの記録は変更しません。

localhostへの接続が制限される開発環境では、補助的に `node scripts/check-file-ui.mjs` で画面操作を確認できます。これはテスト用に組み立てたローカルファイルを開く方法で、PWAのHTTP／HTTPS確認の代わりにはなりません。実施済みの範囲は[検証結果](docs/VALIDATION.md)に記載しています。

## 同じWi-Fiでスマートフォンから試す

`127.0.0.1`は開いている端末自身を指すため、スマートフォンからこのパソコンへは接続できません。同じWi-Fi内で試す場合は、パソコン側で次を実行します。

```sh
pnpm build
pnpm preview:lan
```

端末に表示された `Network: http://192.168.…:4174/` をスマートフォンのChromeで開きます。パソコンとスマートフォンを同じWi-Fiへ接続し、パソコンの起動とプレビューを維持してください。Windowsのアクセス許可が求められた場合は、自宅など信頼できるプライベートネットワークだけを許可します。ゲストWi-Fiでは端末間通信が禁止されることがあります。ルーターのポート開放は不要です。

このHTTPプレビューではチェックとlocalStorage保存を試せます。PWAのインストール・オフライン利用は、下記のHTTPS公開URLで確認してください。ネットワーク上のHTTPは通常セキュアコンテキストにならず、Service Workerを登録できません。[ブラウザの仕様](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)

パソコンのIPアドレスは変わる場合があります。また、プレビューから本番URLへ変えると保存領域も変わります。実際の記録を移すときは、設定のバックアップを使います。

## スマートフォンで使うための公開手順

**GitHub Pagesに対応しました。** 公開後はパソコンの電源を切っていてもHTTPS URLから使えます。Firebase・外部データベース・通知サービスは不要です。記録は引き続き端末のlocalStorageだけに保存します。

初心者向けの操作を [GitHub Pages公開ガイド](docs/GITHUB_PAGES.md) にまとめています。

1. GitHub FreeでPublicリポジトリ（例：`okusuri-check`）を作ります。
2. Settings → Pages → Sourceを「GitHub Actions」にします。
3. `okusuri-check-github-source.zip`を展開し、中身をリポジトリ直下へアップロードします。`.github/workflows/pages.yml`も必ず含めます。
4. Actionsの「Publish to GitHub Pages」が成功したら、Settings → Pages → Visit siteのHTTPS URLをスマートフォンのChromeで開きます。
5. オフライン準備が完了したら、Chromeの「ホーム画面に追加」を実行します。

Actionsは公開先のパスを取得し、Viteのbase・Manifest・アイコン・Service Workerを同じ公開先でビルドします。リポジトリ名を変更しても、コードへ手書きする必要はありません。ソースとワークフローをアップロードすることにより公開が実行されます。この作業フォルダーからGitHubへのアップロードや公開はまだ行っていません。

**以前の自宅Wi-FiのURLとは保存領域が異なります。** 旧URLの設定からバックアップを保存し、GitHub Pagesの新URLで読み込んでください。更新は同じリポジトリ・同じHTTPS URLを使い続けます。

他のホスティングでドメイン直下へ配信する場合は、通常の`pnpm build`で生成する`dist`を使えます。サブパスのローカル確認方法・費用条件・公開時のトラブル対応は公開ガイドを参照してください。

## 保存データについて

**端末・ブラウザごとに独立しています。父母が同じURLを開いても、記録は共有されません。** 同じ端末でもブラウザやプロファイルが違うと別の記録になります。PWAの保存領域の扱いも環境に依存するため、ホーム画面追加後に同じ記録を表示できるか確認してください。

- 保存キーは`okusuri-check.local.v1`。設定、日付別の状態、実施・訂正・尿量変更の履歴をまとめて保存します。
- 保存が拒否されたり容量が不足した場合はエラーにし、実施済みへ変更しません。
- 壊れた保存データを検出した場合、自動で初期化して上書きしません。元データの書き出しとバックアップからの復元を案内します。
- ブラウザデータの削除、端末交換、シークレットモードの終了などで記録が失われることがあります。localStorageは外部バックアップではありません。
- 設定 →「バックアップを保存」でJSONファイルを保存できます。復元はファイル形式を確認し、確認画面で承認した場合だけ現在の記録全体を置き換えます。確認中に別のタブで変更された場合は復元を止めます。
- 実施時刻・日付は端末の時計に依存します。Androidの日時の自動設定を有効にしてください。閉じている間に処理を実行する必要はなく、次回起動時に当日を用意します。使わなかった日の空の記録は作りません。
- 一時薬の有効・無効は保存後すぐに当日に反映し、翌日にも引き継ぎます。実施済み時刻と過去日の記録は変更しません。終了した薬は「対象外」と表示します。
- 同じブラウザの複数タブでは、保存の都度最新データを読み直し、対応環境ではWeb Locksで競合を防ぎます。Web Locks非対応環境では単一タブでの利用を推奨します。

保存領域の仕様：[localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。ログインによる保護や暗号化は行わないため、この端末・このブラウザを操作できる人は記録を確認できます。薬の記録はホスティング先へ送信しません。公開されるのはアプリの画面・コード・アイコンです。

## ファイル構成

- `src/App.tsx`、`src/components/`：今日・履歴・設定・確認画面。
- `shared/domain.ts`：薬、条件判定、実施・訂正・日付のロジック。
- `src/localStore.ts`：localStorageの読み書き、検証、バックアップ。
- `src/useToday.ts`：0時・再表示・同一ブラウザ内の変更への対応。
- `src/sw.ts`、`scripts/build-sw.mjs`：同じサイトの静的ファイルをオフライン用に保存。
- `public/manifest.webmanifest`、`public/_headers`：PWAと静的配信の設定。
- `tests/`：判定・保存・ブラウザテスト。
